# Mini NPU 시뮬레이터

패턴과 두 필터의 MAC 점수를 계산해 어떤 필터와 더 유사한지 판정하는 Python 콘솔 프로그램입니다.

## 실행 방법

Python 3.8 이상에서 표준 라이브러리만 사용합니다. `main.py`와 제공된 `data.json`을 같은 폴더에 두고 실행합니다.

```sh
python3 main.py
```

- **모드 1**은 필터 A, 필터 B, 패턴을 차례로 받습니다. 각 행에 숫자 3개를 공백으로 구분해 입력합니다. 잘못된 행은 같은 행부터 다시 입력합니다.
- **모드 2**는 `data.json`의 각 케이스를 판정하고 기대 라벨과 비교합니다. 이어서 크기별 성능 표와 실패 요약을 출력합니다. 파일은 `main.py`의 위치를 기준으로 찾습니다.
- 두 모드의 성능 표에서 기존 2차원 MAC과 보너스 과제의 1차원 MAC 평균 시간을 비교할 수 있습니다.

## 구현 요약

- 패턴과 필터는 `matrix[row][column]`으로 접근할 수 있는 2차원 리스트입니다. MAC은 두 행렬의 같은 위치를 곱해 하나의 점수에 순서대로 누적합니다. AI 모델도 이미지의 일부와 필터를 비교할 때 이 연산을 여러 위치와 필터에 반복해 특징을 검출합니다.
- 모드 2는 `size_{N}_{idx}`에서 `N`을 읽어 `filters.size_{N}`을 선택합니다. 필터 두 개와 입력 패턴이 각각 `N`행이고 모든 행에 유한한 숫자가 `N`개인지 검증합니다.
- 필터 키 `cross`와 `x`는 각각 `Cross`와 `X`로 저장합니다. 기대 라벨 `+`와 `x`도 같은 표준 라벨로 변환한 뒤 판정과 비교합니다.
- 두 점수의 차이의 절댓값이 `1e-9` 미만이면 `UNDECIDED`로 판정합니다. 차이가 `1e-9` 이상이면 점수가 높은 쪽을 선택합니다.

## 결과 리포트

### 케이스별 판정

제공된 `data.json`에서 총 6개 중 3개가 통과했고, 3개는 동점 처리 정책에 따라 실패했습니다.

| 케이스 | Cross 점수 | X 점수 | 기대 라벨 | 판정 | 결과 |
| --- | ---: | ---: | --- | --- | --- |
| `size_5_1` | 0.9 | 0.8999999999999999 | X | UNDECIDED | FAIL |
| `size_5_2` | 8.9 | 0.1 | Cross | Cross | PASS |
| `size_13_1` | 0.3 | 14.700000000000008 | X | X | PASS |
| `size_13_2` | 7.499999999999997 | 7.5 | Cross | UNDECIDED | FAIL |
| `size_25_1` | 4.9 | 4.899999999999999 | X | UNDECIDED | FAIL |
| `size_25_2` | 52.9 | 0.1 | Cross | Cross | PASS |

### 실패 원인

1. **데이터와 스키마.** 제공된 케이스는 모두 키 형식, 행렬 크기, 숫자 형식, 기대 라벨 검증을 통과했습니다.
2. **라벨 비교.** `+`와 `x`를 표준화해 `Cross`와 `X` 판정에 바로 비교할 수 있습니다. 허용 목록에 없는 값은 기대 라벨 오류로 기록합니다.
3. **수치 표현.** 일부 소수는 이진 부동소수점으로 정확히 표현할 수 없어, 곱셈과 덧셈을 거치면서 작은 반올림 오차가 생깁니다. 예를 들어 `0.3 + 0.3 + 0.3`은 `0.8999999999999999`입니다.
4. **동점 기준.** `size_5_1`, `size_13_2`, `size_25_1`의 점수 차이는 각각 약 `1.11e-16`, `2.66e-15`, `1.78e-15`입니다. 세 차이가 모두 `1e-9` 미만이어서 `UNDECIDED`로 판정했습니다. 교차 검증을 위해 JSON의 소수를 `Decimal`로 읽어 다시 계산했을 때 두 점수는 케이스별로 각각 0.90, 7.50, 4.90으로 같았습니다.
5. **통과 기준.** `UNDECIDED`는 기대 라벨 `Cross` 또는 `X`와 일치할 수 없으므로 세 케이스 모두 FAIL입니다. 나머지 세 케이스는 허용오차보다 점수 차이가 크고, 점수가 높은 필터의 라벨이 기대 라벨과 일치합니다.
6. **로직 점검.** 3×3 십자가를 A, X를 B에 넣고 X 패턴을 입력했을 때 A는 1, B는 5로 B 판정이 나왔습니다. 소수 합산 결과만 미세하게 다른 입력은 판정 불가로 표시됐습니다.
7. **오류 재현.** 임시 JSON에서 패턴의 행과 열을 각각 줄이고, 잘못된 기대 라벨과 키를 입력해 해당 케이스에 실패 사유가 남고 다른 케이스는 계속 처리되는 것을 확인했습니다. 필터 크기를 바꾸면 그 필터 그룹을 참조하는 케이스에 검증 오류가 표시됩니다.

### 성능과 시간 복잡도

| 크기 | 2차원 MAC 평균(ms) | 1차원 MAC 평균(ms) | MAC 1회 연산 횟수(N²) |
| --- | ---: | ---: | ---: |
| 3×3 | 0.001093 | 0.000589 | 9 |
| 5×5 | 0.002082 | 0.001268 | 25 |
| 13×13 | 0.009325 | 0.006926 | 169 |
| 25×25 | 0.030652 | 0.027401 | 625 |

1. **측정 조건.** 위 표는 Python 3.14.3에서 모드 2를 한 번 실행한 결과입니다. 크기마다 같은 패턴과 필터로 각 방식을 1,000회씩 호출하고, `perf_counter_ns()`로 측정한 MAC 1회 평균을 밀리초로 표시했습니다.
2. **측정 입력.** 모드 2는 크기별로 생성한 십자가 패턴과 같은 크기의 십자가 필터를 사용합니다. 모드 1은 입력받은 패턴과 필터 A를 사용합니다. 파일 읽기, 유효성 검사, 행렬 준비와 1차원 변환, 콘솔 출력은 측정 구간 밖에서 수행합니다.
3. **연산 횟수.** 한 필터의 점수를 계산할 때 `N`개의 행에서 `N`개 위치를 방문해 각 위치마다 곱셈과 누적 덧셈을 한 번씩 합니다. 따라서 MAC은 정확히 `N²`번 수행되고, 시간 복잡도는 `O(N²)`입니다.
4. **두 필터 판정.** 패턴 하나는 두 필터와 비교하므로 점수 계산에 총 `2N²`번의 MAC이 필요합니다. 점수 비교는 일정한 시간이 걸려 전체 판정의 시간 복잡도는 `O(N²)`입니다.
5. **측정 해석.** 5×5에서 25×25로 바꾸면 MAC 횟수는 25회에서 625회로 25배 증가합니다. 측정된 평균 시간은 2차원 방식에서 약 14.7배, 1차원 방식에서 약 21.6배 증가했습니다. 함수 호출과 타이머 비용, 실행 환경의 영향으로 측정 비율은 달라질 수 있습니다.

### 보너스 과제 1차원 배열 최적화

검증된 행렬의 행을 차례로 이어 붙여 길이 `N²`인 리스트로 변환합니다. 기존 `matrix[row][column]`의 값은 `flat[row * N + column]`에 놓입니다. `mac_flat()`은 두 리스트를 한 번씩 순회하며 기존과 같은 순서로 곱하고 더합니다. 두 모드의 판정에 이 함수를 적용했습니다. 패턴은 두 필터와 비교하기 전에 한 번 변환하고, JSON 필터는 로드할 때 변환한 리스트를 같은 크기의 케이스마다 재사용합니다.

제공된 패턴 6개를 각 필터와 비교한 점수 12개가 두 방식에서 정확히 일치했습니다. 위 측정에서 1차원 방식의 MAC 평균 시간은 3×3에서 약 46%, 25×25에서 약 11% 줄었습니다. 변환에도 행렬당 `O(N²)` 시간이 필요하므로 이 감소율은 변환된 리스트를 준비한 뒤의 MAC 호출에 해당합니다.

0 1 0

1 0 1
